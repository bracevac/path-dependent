Scala's capture checker can also say what kind of capabilities a value may use. A capability class may extend a classifier, such as $\mathit{Control}$, and a capture set can keep only the capabilities of one classifier, or exclude them. Scala filters \lstinline{any} itself, as in \lstinline{any.except[Control]}, so the tree \treeCL is a copy of \treeCC, which reads \lstinline{any} as the compiler does. It keeps the proof of Sections~\ref{sec:target} and~\ref{sec:levels} and changes once more what the roots of a capture set are: a filter drops the roots whose classifier it excludes. Every theorem of this section is in \treeCL.

\subsection{Programs and promises}\label{sec:cl-programs}

Section~\ref{sec:cc-later} quoted \lstinline{Try.apply} and described \lstinline{runOnNewThread}. \treeCL models both after Capless(K) \cite{pham2026classifying}. In place of \lstinline{runOnNewThread} it has Capless(K)'s \lstinline{Future.apply}, whose body may use anything but a thread-local capability. Its model is a pure closure of type
\[
\src{\capt{(\dall{\kappa, x}{\capt{(\dall{\kappa', w}{\Unit}{\Unit})}{\cset{\restr{\cany}{\kexcept{\mathit{ThreadLocal}}}}}}{\capt{\dmu{z}{\dfld{\mathit{body}}{\capt{(\dall{\kappa', w}{\Unit}{\Unit})}{\cset{z}}}}}{\cset{x}}})}{\cempty}}\!,
\]
whose result is an object that stands for the \lstinline{Future} value. \lstinline{Try.apply} has the same shape over a platform whose capabilities $\kappa_{\mathit{ctl}}$ and $\kappa_{\mathit{io}}$ declare the classifiers $\mathit{Control}$ and $\mathit{IO}$. Its parameter set is $\src{\cset{\kappa_{\mathit{ctl}}, \kappa_{\mathit{io}}}}$, and its result set $\src{\cset{\restr{x}{\konly{\mathit{Control}}}}}$ is Scala's \lstinline{body.only[Control]}, with the parameter $x$ for \lstinline{body} (Section~\ref{sec:cl-filter}). The Lean's promise is about a whole program and a kind, a set of classifiers (Section~\ref{sec:cl-kinds}). If every root of the program's use set has a classifier that the kind contains, so has every root of a variable that its run inspects (Theorem~\ref{thm:cl-effect}). Neither model runs the closure it is passed. So at a call of either the promise holds for want of a root (\lean{E1\_effect\_safety}, \lean{E2\_effect\_safety}, built by hand), and Section~\ref{sec:cl-instances} calls the closure itself. The promise of \lstinline{Try.apply} in Section~\ref{sec:cc-later} concerns the result of one call, and no theorem states it.

A classifier is a node of a tree: $\top$ is the top node and $\clchild{n}{k}$ the $n$-th child of $k$ (Figure~\ref{fig:cl-syntax}). The order $k \le k'$ says that $k$ lies in the subtree of $k'$. The examples use the tree of Capless(K). A $\mathit{Control}$ capability is bound to the stack of its thread (\texttt{classifiers.md}, line 126), and Capless(K) puts $\mathit{Control}$ below $\mathit{ThreadLocal}$. So $\kexcept{\mathit{ThreadLocal}}$ excludes $\mathit{Control}$ too, and \lstinline{Future.apply} can replace \lstinline{runOnNewThread}.

A kind is a list of subtrees $\langle k, \vec{k}\rangle$, each the classifiers below $k$ that lie below no classifier of $\vec{k}$, and $\kcont{k}{\chi}$ says that $\chi$ contains $k$. So $\konly{\mathit{Control}}$ contains $\mathit{Control}$ and no other classifier of the examples, and $\kexcept{\mathit{ThreadLocal}}$ contains $\top$ and $\mathit{IO}$ but neither $\mathit{ThreadLocal}$ nor $\mathit{Control}$. The subkind test $\subkind{\chi}{\chi'}$ subtracts the subtrees of $\chi'$ from $\chi$ one at a time and asks that nothing be left. Its sound half is proved: $\subkind{\chi}{\chi'}$ and $\kcont{k}{\chi}$ give $\kcont{k}{\chi'}$ (\lean{Kind.Subkind.contains}), the only fact about subkinding used here. The converse is not proved, so the subkind test is not known to be reflexive or transitive (Section~\ref{sec:mech-trees}).

\subsection{Filtered capture sets and their roots}\label{sec:cl-filter}

The atom $\restr{c}{\chi}$ is Scala's \lstinline{c.only[A]}, or \lstinline{c.except[A]} with an exclusion kind. It is an atom, not an operation on the set, and resolution carries it to the roots, where the filter acts after expansion (Example~\ref{ex:cl-filter}). A set $\restr{C}{\chi}$ filters each atom of $C$, and a second filter intersects the kinds. No term binds a classified binder $\kappa : \clsb{k}$, so a program finds them on its platform.

\begin{lemma}[Roots of a filtered set, \leanin{Ctx.roots\_proj}{\treeCL}]\label{lem:cl-roots-proj}
For every $\Gamma$, $n$, $C$ and $\chi$, $\rootsn{\Gamma}{n}{\restr{C}{\chi}} = \cset{b \in \rootsn{\Gamma}{n}{C} \mid \kcont{\clsof{\Gamma}{b}}{\chi}}$.
\end{lemma}

The roots read a star binder, a platform capability of no class, as the classifier $\top$, which $\konly{\mathit{Control}}$ drops and $\kexcept{k}$ keeps for $k \neq \top$. So Theorem~\ref{thm:cl-effect} at $\kexcept{\mathit{ThreadLocal}}$ protects only the capabilities declared thread local. Scala reads such a capability as unknown. Its \lstinline{c.only[A]} keeps it, and its \lstinline{c.except[A]} refuses it (\texttt{classifiers.md}, lines 113 and 148). Under either filter, \rn{C-Proj} needs kinding, and \rn{Kd-Cls} and \rn{Kd-Proj} refuse a bare star binder (Example~\ref{ex:cl-k6}).

\begin{example}[Filtered roots, built by hand]\label{ex:cl-filter}
Let $\Gamma_{T} = \kappa_{\mathit{ctl}} : \clsb{\mathit{Control}},\ \kappa_{\mathit{io}} : \clsb{\mathit{IO}}$, the platform of \lstinline{Try}, and $\Gamma_{\varrho} = \kappa_{\mathit{tl}} : \clsb{\mathit{ThreadLocal}},\ \varrho : \scopeb,\ \kappa_{\mathit{ctl}} : \clsb{\mathit{Control}}$. Then
\[
\begin{array}{@{}lcl@{}}
\rootsn{\Gamma_{T}}{0}{\cset{\restr{\kappa_{\mathit{ctl}}}{\konly{\mathit{Control}}}}} & = & \cset{\kappa_{\mathit{ctl}}} \\
\rootsn{\Gamma_{T}}{0}{\cset{\restr{\kappa_{\mathit{io}}}{\konly{\mathit{Control}}}}} & = & \cempty \\
\rootsn{\Gamma_{\varrho}}{0}{\cset{\restr{\varrho}{\kexcept{\mathit{ThreadLocal}}}}} & = & \cset{\topc, \varrho}
\end{array}
\]
by \lean{K1x\_roots\_ctl}, \lean{K1x\_roots\_io} and \lean{K3x\_roots}. The third set is \lstinline{any.except[ThreadLocal]} in a scope whose local $\cany$ is $\varrho$ (Section~\ref{sec:levels-scopes}). Expansion opens $\varrho$ into $\topc$, $\kappa_{\mathit{tl}}$, $\varrho$ and $\kappa_{\mathit{ctl}}$, and the filter drops $\kappa_{\mathit{tl}}$ and $\kappa_{\mathit{ctl}}$, as $\mathit{Control}$ lies below $\mathit{ThreadLocal}$. Filtering first would keep $\varrho$, which expansion would then reopen into $\kappa_{\mathit{tl}}$ and $\kappa_{\mathit{ctl}}$ (on paper). In $\Gamma_{\varrho}$, which no program builds, the set does not cover $\kappa_{\mathit{ctl}}$ (\lean{K3x\_not\_capLe}).
\end{example}

A call of \lstinline{Future.apply} shows why kinding needs evidence. Let $\src{f}$ be bound to its model over the platform $\kappa_{\mathit{tl}} : \clsb{\mathit{ThreadLocal}},\ \kappa_{\mathit{ctl}} : \clsb{\mathit{Control}},\ \kappa_{\mathit{io}} : \clsb{\mathit{IO}}$. A call $\src{f\,b}$ instantiates the $\cany$ of its parameter set at $\src{b}$ (Section~\ref{sec:levels-rule}) and checks $\src{b}$ at $\src{\cset{\restr{b}{\kexcept{\mathit{ThreadLocal}}}}}$, while \rn{Var} types $\src{b}$ at $\src{\cset{b}}$. Evidence must show that the filter drops no root of $\src{b}$.

A kinding judgment $\kindj{\Gamma}{g}{C}{\chi}$ says that $g$ shows every root of $C$ to have a classifier in $\chi$ (Figure~\ref{fig:cl-kinding}). An atom carries its filters. $\baseof{c}$ is the atom under them, and $\kindof{c}$ is the intersection of their kinds, $\konly{\top}$ for a bare atom. \rn{Kd-Proj} kinds an atom whose kind is below $\chi$, so a bare atom only at a $\chi$ that contains every classifier. \rn{Kd-Cls} kinds a classified binder under its filters. Its classifier must lie in $\chi$ unless those filters already drop it. \rn{Kd-Var}, \rn{Kd-CVar} and \rn{Kd-Member} read a variable, an instance binder or an object type, as \rn{C-Var} and \rn{C-Member} do. \rn{C-Proj} closes the gap of the call above, since a set kinded at $\chi$ loses nothing under the filter $\chi$. The templates \rn{M-Kind} and \rn{M-KindLe} build the casts that translate the source rules \rn{CapK} and \rn{CapK-I} below. \rn{M-Kind} takes the step $\admstep{\chi_1}{\chi_2}$ so that it can keep the kind, since the subkind test is not known to be reflexive.

\begin{theorem}[Canonical forms of closed kinding evidence, \leanin{kind\_canon}{\treeCL}]\label{thm:cl-kind}
Let $\storej{\sigma}{\Gamma}$. If $\kindj{\Gamma}{g}{C}{\chi}$, then $\kindle{\Gamma}{C}{\chi}$.
\end{theorem}

\begin{proof}[Proof sketch]
By induction on $g$, mutually with Theorem~\ref{thm:target-canon}, since \rn{Kd-Var}, \rn{Kd-Member} and \rn{Kd-Le} read atom typings or capture evidence and \rn{C-Proj} reads kinding. \rn{Kd-Cls} holds as a classified binder is its own only root. \rn{Kd-Proj} and \rn{Kd-Sub} hold by the sound half of the subkind test, and \rn{Kd-Le} by item~1 of Theorem~\ref{thm:target-canon}, since a set covered by a kinded set is kinded. \rn{Kd-Var} and \rn{Kd-CVar} follow from the typing of $b$ or the instance binder with Lemma~\ref{lem:cl-roots-proj}, which also gives \rn{Kd-ProjS} and the new cases of Theorem~\ref{thm:target-canon}. The other cases go as there.
\end{proof}

\subsection{Classified prediction and effect safety}\label{sec:cl-runtime}

\begin{theorem}[Classified prediction and effect safety, \leanin{classified\_prediction}{\treeCL} and \leanin{classified\_effect\_safety}{\treeCL}]\label{thm:cl-effect}
Let $\statej{\mathit{st}}{T}$, let $\storej{\sigma}{\Gamma}$ for the store $\sigma$ of $\mathit{st}$, and let $\kindle{\Gamma}{\uses{\mathit{st}}}{\chi}$. Let $\mathit{st} \steps \mathit{st}'$, where the store $\sigma'$ of $\mathit{st}'$ has $\storej{\sigma'}{\Gamma'}$.
\begin{enumerate}
\item $\sext{\sigma}{\sigma'}$, $\caple{\Gamma'}{\uses{\mathit{st}'}}{\uses{\mathit{st}}}$ and $\kindle{\Gamma'}{\uses{\mathit{st}'}}{\chi}$.
\item If $\insp{\mathit{st}'} = x$, then $\kindle{\Gamma'}{\cset{x}}{\chi}$.
\end{enumerate}
\end{theorem}

Item~1 is capture prediction, Theorem~\ref{thm:target-uses} in \treeCL's copy, with two facts. A set covered by a kinded set is kinded, and store extension keeps kinding, since it keeps every binder's classifier (\lean{Ctx.KindLe.mono}, \lean{Store.Ext.kindLe}). Item~2 follows, since an inspected variable is covered by the use set (\lean{inspects\_covered}, Remark~\ref{rem:mini-insp}).

\begin{theorem}[Classified effect safety for \DOTMNF, \leanin{dot\_classified\_effect\_safety'}{\treeCL}]\label{thm:cl-source}
Let $\plat$ be a platform, $\src{h}$ a derivation of $\dtyuj{U}{\platctx}{t}{T}$ at a type $\src{T}$, not an existential answer, and $\src{g}$ a derivation of $\kindsj{\platctx}{U}{\chi}$. Let $\mst{\platstore}{\cdot}{\src{t}} \steps \src{\mathit{st}}$ with $\insp{\src{\mathit{st}}} = x$. Then there are a target state $\tstate$ with store $\sigma'$ and a context $\Gamma'$ such that $\mst{\tplatstore}{\cdot}{\trans{h}} \steps \tstate$, $\tstate$ is typed, $\insp{\tstate} = x$, $\erase{\tstate} = \erase{\src{\mathit{st}}}$, $\storej{\sigma'}{\Gamma'}$, $\sext{\tplatstore}{\sigma'}$, and $\kindle{\Gamma'}{\cset{x}}{\chi}$.
\end{theorem}

The translation of $\src{g}$ is typed kinding evidence, so Theorem~\ref{thm:cl-kind} at the platform's store gives $\kindle{\trans{\platctx}}{\trans{U}}{\chi}$. The proof of Theorem~\ref{thm:source-effect} then goes through with Theorem~\ref{thm:cl-effect} for effect safety.

\subsection{Instances}\label{sec:cl-instances}

\begin{example}[A filtered closure, called, built by hand]\label{ex:cl-try}
E2r replaces the call $\src{f\,b}$ of Example~\ref{ex:cl-future} by a call of $\src{b}$ on a pure closure $\src{u}$: $\src{\klet u = \lambda(x : \Unit).\,x \kin \klet b = \lambda(x : \Unit).\,x \kin \klet r = b\,u \kin r}$. Its derivation types $\src{b}$ at $\src{\restr{\cset{\kappa_{\mathit{tl}}, \kappa_{\mathit{ctl}}, \kappa_{\mathit{io}}}}{\kexcept{\mathit{ThreadLocal}}}}$, the program's use set. \rn{Kd-Cls} kinds that set at $\kexcept{\mathit{ThreadLocal}}$, as Theorem~\ref{thm:cl-source} asks. The run inspects $\src{b}$ at the call. There $\kappa_{\mathit{io}}$ is a root of $b$ in the matched target state, so the instance is informative (Example~\ref{ex:mini-prog2}). The instance at the call rules out $\kappa_{\mathit{tl}}$ and $\kappa_{\mathit{ctl}}$, which the filter dropped. E1r is the same program at $\konly{\mathit{Control}}$ over the platform of \lstinline{Try}, with the root $\kappa_{\mathit{ctl}}$. The Lean states these facts as \lean{E2r\_typed}, \lean{E2\_kind}, whose side conditions are decided, \lean{E2r\_reads\_root}, \lean{E2r\_read\_has\_root}, \lean{E1r\_reads\_root} and \lean{E1r\_read\_has\_root}.
\end{example}

\subsection{What is not proved}\label{sec:cl-open}

\begin{example}[An incompleteness]\label{ex:cl-k6}
Kinding is incomplete at a star binder. Let $\Gamma = \kappa_{\mathit{tl}} : \clsb{\mathit{ThreadLocal}},\ \kappa_p : \cstar$. The star binder $\kappa_p$ has classifier $\top$, which $\kexcept{\mathit{ThreadLocal}}$ contains, so $\kindle{\Gamma}{\cset{\kappa_p}}{\kexcept{\mathit{ThreadLocal}}}$ (\lean{K6x\_kindLe}, built by hand). Yet no evidence derives it (\lean{K6x\_no\_kindCo}, built by hand). \rn{Kd-Cls} needs a declared classifier, and \rn{Kd-Proj} needs $\subkind{\konly{\top}}{\kexcept{\mathit{ThreadLocal}}}$, which fails (\lean{K6x\_kcls\_reject} and \lean{K6x\_kproj\_reject}, decided). Refusing is right: in a lambda body $\kappa_p$ may be the capture binder of a parameter, which a call instantiates at its argument, possibly a thread-local capability. The Lean proves \lean{K6x\_no\_kindCo} by the renaming of an unpacking instead (Section~\ref{sec:history}).
\end{example}

No theorem says that the \lstinline{Future} program with a thread-local argument has no typing derivation. Theorem~\ref{thm:cl-kind} needs a typed store, so it says nothing about kinding inside a lambda body, and the source theorems apply it at the platform only.
