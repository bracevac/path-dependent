\section{What Report~1 Provides}\label{sec:recap}
\mathtgt

This section recalls the pieces of \Rone that Sections~\ref{sec:mini} and~\ref{sec:target} use, each by its number in report~1, and says what changes when types carry capture sets. Section~\ref{sec:target-canon} recalls the one theorem the proof reuses, with its hypotheses.

\paragraph{Types and evidence.}
An object type of \FCdot is a telescope of propositions about a self, and $\top$ is the empty one, $\obj{\tnil}$ (Section~\ref{R1-sec:mini-types} of report~1). A block name $\sel{x}{\ell}$ names the member $\ell$ of a variable $x$, whatever the type of $x$. Every use of subtyping is evidence, a proof term that erases to nothing. Evidence determines its endpoints in a given context, so a checker reads it without inference. The rule for $\ev{member}$ reads one proposition of an object type at an atom (Figure~\ref{R1-fig:evidence} of report~1).

\paragraph{Atoms and roots.}
There is no subsumption in \FCdot. Where DOT retypes a variable, \FCdot wraps it in a cast, and a variable under casts is an atom (Section~\ref{R1-sec:mini-terms} of report~1). The full calculus adds atoms that fold and unfold an object type at its variable, and an atom that pairs two typings of one variable (Section~\ref{R1-sec:atoms} of report~1). The root of an atom, $\rt{a}$, is the variable under all of these. Types see only the root of an atom. So a cast changes what is known about a variable, never which variable it is. This report also speaks of the roots of a capture set (Section~\ref{sec:mini-roots}). An atom has one root, a term variable. A capture set has a set of roots, which are capture variables. When this report speaks of the roots of a variable $x$, it means the roots of the capture set $\cset{x}$, never $\rt{x}$, which is $x$ itself.

\paragraph{Inert stores.}
A context has opaque binders, which a lambda parameter or a let introduces, and transparent binders, which define the block of their variable. A store holds one value per location, a lambda or a literal, never a cast. Store typing $\storej{\sigma}{\Gamma}$ types each value at its precise type, in the context of the entries before it, and binds its location transparently (Section~\ref{R1-sec:mini-machine} of report~1). The store is inert, so the type of a location asserts what its value defines and nothing more. Evidence is closed when it is typed in the context of a typed store, so that every free variable is a location.

\paragraph{The machine.}
A state $\mst{\sigma}{K}{t}$ has a store, a continuation of let frames and cast frames, and a term (Figure~\ref{R1-fig:mini-machine} and Figure~\ref{R1-fig:machine} of report~1). Allocation stores $\mathit{core}(v)$, the value under its casts, and continues with $\mathit{adjust}(u, v)$, which hands the stripped casts to the body $u$. Application through a variable is $\beta$ on the stored lambda. Application through a cast atom normalizes the chain of casts on the atom. The head form it finds says how to cast the argument and the result.

\paragraph{The slogan.}
Safety rests on one theorem about closed evidence over a typed store (Section~\ref{R1-sec:idea} of report~1). Report~1's Theorem~\ref{R1-thm:canon} normalizes such evidence to a typed head form, by structural induction on its typing. Progress then inverts the head form by a look at its shape, and no typing derivation of evidence is ever inverted. Bad bounds are not ruled out by the type system. Closed evidence through bad bounds would normalize to a head form that does not exist.

\paragraph{Safety by translation.}
DOT itself is never inverted either. A typed DOT derivation translates to a typed \FCdot program with the same erasure. The proof of report~1's Theorem~\ref{R1-thm:dot-safety} runs the two programs side by side. Its invariant is that some typed target state has the same erasure as the source state. The backward erasure simulation and preservation of the target keep that invariant. Progress of the target, reflected back through erasure, shows that the source never gets stuck.

\paragraph{What changes.}
In this report a type of \FCdot splits into a shape $S$ and a capture set $C$, written $\capt{S}{C}$. The shapes are report~1's types, and Section~\ref{sec:target-boxes} adds a box shape. Evidence for an inclusion of types pairs shape evidence with capture evidence (Section~\ref{sec:target-delta}). Shape evidence keeps report~1's normal forms, in an earlier version of them that Section~\ref{sec:mech-trees} describes. The capture half gets none, and Section~\ref{sec:mini} shows on a fragment that it needs none. What the proof asks of capture evidence for $C \le D$ is that every root of $C$ is a root of $D$. Section~\ref{sec:mini-roots} defines roots. Capture members bring bad bounds back for capture sets (Section~\ref{sec:problem-bad}), and there the typed store enters again (Section~\ref{sec:target-canon}).
