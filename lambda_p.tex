\title{\texorpdfstring{\lambdap}{lambda-p}: Paths through Dependent Pairs}
\author{Oliver Bra\v{c}evac}
\author{Martin Odersky}
\renewcommand{\shortauthors}{Bra\v{c}evac and Odersky}
\authorsaddresses{}

\begin{document}

\begin{abstract}
We present \lambdap{}, a calculus in which paths traverse immutable dependent
pairs. A pair member may depend on the first component and may contain either
a term reference or a type definition. The calculus distinguishes term
singleton types from abstract type selections. Conflating the two makes
singleton symmetry unsound: we give a closed, well-typed program that becomes
stuck. We restrict dependent-member subtyping to pairs whose first component
has singleton type and prove type safety in Lean. The unrestricted pair rule
remains an open question.
\end{abstract}

\keywords{path-dependent types, dependent pairs, singleton types, type
soundness, Lean}

\maketitle

\section{Introduction}

A path-dependent type assigns a type component to a stable term path. DOT
presents this mechanism together with recursive objects, refinements,
intersections, unions, and declarative subtyping
\citep{amin2014foundations,rompf2016dot}. \lambdap{} isolates paths, abstract
type members, and dependency between the two components of a pair.

\lambdap{} is a call-by-value calculus in monadic normal form whose values are
functions and immutable dependent pairs. Paths are formed from variables,
first projections, and labelled selections. A pair stores a first component
together with either a term reference or a type definition, and its member
signature may depend on the first component. Chains of pairs encode records:
lookup resumes through the first component when the outer label differs. Term
singleton types record path identity, while abstract selections range over
explicitly checked lower and upper bounds. The static semantics includes
dependent functions and declarative subtyping with primitive transitivity;
evaluation combines big-step path resolution with a CK machine over an
append-only store.

For example, let \(r_1=\pairval{b}{a}{z}\) and
\(r_2=\pairval{r_1}{A}{T}\). Selection \(r_2.A\) hits the outer type member,
whereas \(r_2.a\) misses \(A\) and continues as \(r_2.1.a\), eventually
returning \(z\). The signature of the outer member may refer to its binder for
\(r_1\), so the same pair structure supports both record extension and
dependency on the preceding component.

The proof relies on two design choices. First, the singleton type
\(\sing{p}\), which expresses value identity, is distinct from the abstract
selection \(p.A\), which denotes a type between declared bounds. An earlier
version represented both with one constructor. We show that singleton
symmetry then turns abstract membership into a false path equality and yields
a closed stuck program.

Second, changing the dependent member requires a singleton type for the first
component; widening the first component is a separate rule. The member premise
is opened at the singleton path, providing the comparison used by the semantic
interpretation. Soundness of the unrestricted rule with distinct singleton
and selection types remains open.

\paragraph{Contributions.}
The paper gives a closed counterexample showing that abstract membership
cannot justify singleton symmetry; a calculus that separates those notions
and retains dependent abstract members with explicit bound checks; and a
type-safety proof based on exact stores, runtime path equivalence, and an
inductive interpretation of subtyping by semantic coercions. The sound
calculus, the regression excluding the critical false alias, and the safety
proof are formalized in Lean 4 \citep{demoura2021lean4}. Recursive objects,
recursive types, mutation,
intersections, and unions lie outside the core language; termination, type
inference, and elimination of primitive transitivity lie outside the present
development.

The binder \(x\) in a function scopes over its codomain. In
\(\pairty{x}{S}{a}{\tau}\), it scopes over the member signature \(\tau\).
We write \(\subst{\tau}{p}{x}\) for capture-avoiding opening. Terms are in
monadic normal form: pair components are variables, and both sides of an
application are paths.

The static semantics consists of precise path typing, subtyping,
well-formedness of member signatures, and term typing. The double colon marks a
synthesis judgment without subsumption; term typing admits subsumption through
\textsc{T-Sub}.

\section{Two design decisions}
\label{sec:pairs}

\subsection{Singletons and abstract selections}

The term singleton \(\sing{p}\) asserts value identity. In particular,
\textsc{S-Alias} is justified when precise typing says that one path has
another path's singleton type. An abstract selection \(p.A\) denotes an
unknown type between the bounds stored at \(A\); membership in \(p.A\)
carries no path-equality information.

In a precursor to \lambdap{}, both forms used one type constructor, so
singleton symmetry accepted either role. Let
\[
\begin{array}{rcl}
f &=& \lambda(x:\top).x,\\
q &=& \pairval{f}{A}{\top},\\
h &=& \lambda(z:q.A).q.
\end{array}
\]
The historical rules type the body of \(h\) by the chain
\[
  \sing{q}<:\top<:q.A<:\sing{z}.
\]
The last edge applies singleton symmetry to the context binding \(z:q.A\),
treating abstract membership as equality. The same rules accept \(f\) as an
argument of type \(q.A\). The application \(h\,f\) therefore evaluates to
\(q\) despite receiving the result type \(\sing{f}\).

Consequently, the closed program
\[
\begin{array}{l}
\mathbf{let}\ f=\lambda(x:\top).x\ \mathbf{in}\\
\mathbf{let}\ q=\pairval{f}{A}{\top}\ \mathbf{in}\\
\mathbf{let}\ h=\lambda(z:q.A).q\ \mathbf{in}\\
\mathbf{let}\ r=h\,f\ \mathbf{in}\ r\,f
\end{array}
\]
reaches an application whose operator location contains the pair \(q\). It is
neither final nor reducible. Every interval in the derivation is
\(\top..\top\), so all bounds pass the consistency check. An admissible
transitivity lemma would compose the same chain.

In the present syntax, a binding \(z:q.A\) cannot serve as a premise for
\textsc{S-Alias}. The mechanized regression proves that the critical
subtyping \(\sing{q}<:\sing{z}\) remains underivable even with primitive
transitivity.

The counterexample shows that singleton symmetry must distinguish term
identity from abstract membership. Separate constructors make this
distinction explicit.

\subsection{The pair rule}

The unrestricted rule one might first write is
\[
\inferrule
  {\Gamma\vdash S<:S'
   \\
   \Gamma,x:S\vdash\tau<:\tau'}
  {\Gamma\vdash
    \pairty{x}{S}{a}{\tau}
    <:
    \pairty{x}{S'}{a}{\tau'}}.
\tag{Unrestricted Pair}
\]
The premise compares the members under the binder \(x:S\). A runtime pair,
however, contains an actual component \(y\), so preservation requires a
comparison from \(\subst{\tau}{y}{x}\) to \(\subst{\tau'}{y}{x}\). The
semantic interpretation of the rule must be constructed before \(y\) is
known, while its premise yields the required comparison only after the binder
has been instantiated. The finite inductive interpretation used by the proof
has no constructor for such an inhabitant-indexed family.

\textsc{S-Pair-Single} fixes a path \(p\) and provides that specialized
comparison explicitly. If the stored first component \(y\) realizes
\(\sing{p}\), then \(p\) resolves to \(y\), hence \(p\runtimeeq y\).
Conversion transports the opened comparison at \(p\) to the member opened at
\(y\).

The two pair rules derive the following abstraction pattern. If
\(\Gamma\vdash p::P\), then
\[
\begin{aligned}
&\pairty{x}{\sing{p}}{A}{\sing{p}..\sing{p}}
\\[-1mm]
&\quad<:\pairty{x}{\sing{p}}{A}{\bot..\sing{x}}
\\[-1mm]
&\quad<:\pairty{x}{P}{A}{\bot..\sing{x}}.
\end{aligned}
\]
The first step hides an exact definition behind dependent bounds while the
first component is a singleton; the second widens that component.

The semantic interpretation validates the restricted rule. Soundness of the
unrestricted rule remains open; we have neither a proof nor a counterexample
for \lambdap{}.

\section{Soundness}
\label{sec:soundness}

The proof records store locations at their exact introduction types, relates
paths by runtime equivalence, and uses semantic coercions to interpret
subtyping. The operational semantics is the machine in
\cref{sec:dynamics}.

Write \(\steps\) for the reflexive--transitive closure of \(\sstep\).
Thus \(\langle\varnothing,[\,],t\rangle\steps s\) means that execution of
\(t\) from the empty store and continuation reaches \(s\) in finitely many
machine steps. Type safety states non-stuckness for every such state.

\begin{theorem}[Type safety]
\label{thm:safety}
If \(\ctxempty\vdash t:T\) and
\(\langle\varnothing,[\,],t\rangle\steps s\), then
\(s\) is final or there exists \(s'\) such that \(s\sstep s'\).
\end{theorem}

The theorem concerns finite execution prefixes; termination lies outside its
scope. Its proof maintains a stronger runtime invariant over exact stores and
machine states.

Write \(\Delta\struct_{\exact}s:U\) when the store of \(s\) is recorded at
exact introduction types and its current term and continuation satisfy the
auxiliary runtime judgments. Context--type extension is the least relation
generated by
\[
\inferrule
  { }
  {(\Gamma,T)\preceq(\Gamma,T)}
\qquad
\inferrule
  {(\Gamma,T)\preceq(\Delta,U)}
  {(\Gamma,T)\preceq((\Delta,\ell:P),U^\uparrow)}.
\]
Here \(U^\uparrow\) is weakening into the fresh context extension; with the
named presentation used in the paper it has the same concrete syntax as
\(U\).

\begin{theorem}[Reachable-state invariant]
\label{thm:reachable}
If \(\ctxempty\vdash t:T\) and
\(\langle\varnothing,[\,],t\rangle\steps s\), then for some
\(\Delta,U\),
\[
(\ctxempty,T)\preceq(\Delta,U)
\qquad\text{and}\qquad
\Delta\struct_{\exact}s:U.
\]
\end{theorem}

Allocation extends the store context, and preservation weakens the result type
along that extension. The exact-state judgment is the invariant maintained by
machine transitions. \Cref{thm:safety} follows from
\cref{thm:reachable,thm:progress}.

The proof proceeds through the relations defined in
\cref{fig:runtime-proof,fig:auxiliary,fig:runtime-typing,fig:realization,fig:coercions}.
An exact store retains the syntax-directed type of every allocated value.
Endpoint resolution then
follows a well-typed path to a value location or a stored type definition,
and runtime path equivalence accounts for the equalities created by lookup.
The source rules extend to auxiliary judgments closed under conversion along
this equivalence. A simultaneous induction interprets auxiliary path checking
by endpoint realization and auxiliary subtyping by semantic coercions.
Coercion action gives canonical forms, from which progress and preservation
follow.

\subsection{Path resolution and exact stores}

Precise synthesis is not preserved by path resolution. Suppose a stored pair
has first component \(y\). The path \(p.1\) may synthesize \(\sing{y}\),
whereas the endpoint \(y\) synthesizes the type assigned by the store context.
The proof therefore uses checking modulo runtime path equivalence.

\begin{lemma}[Typed path resolution]
\label{lem:path-resolution}
If \(\storeexact(\Gamma;\sigma)\) and
\(\Gamma\struct_{\sigma}p::\tau\), then there is an endpoint \(e\)
such that
\[
\sigma\vdash p\resolve e
\qquad\text{and}\qquad
e\in\llbracket\tau\rrbracket_{\Gamma,\sigma}.
\]
\end{lemma}

If \(\tau=T\), then \(e=\mathsf{val}(x)\); if \(\tau=L..U\), then
\(e=\mathsf{type}(W)\). In the first case, runtime path
equivalence identifies \(p\) with \(x\); singleton conversion and auxiliary
subsumption then re-establish \(\Gamma\struct_{\sigma}x::T\) from
\(\Gamma\struct_{\sigma}p::T\).

Exact stores also supply the inversion needed for canonical forms. An
ordinary store typing may record a location at a supertype of its stored
value, hiding its introduction form. An exact store records the
syntax-directed type assigned by
\textsc{T-Abs}, \textsc{T-Pair}, or \textsc{T-Type-Pair}. Allocation extends
the store with precisely this type; value inversion and narrowing recheck the
suspended let body under the more informative binding.

\subsection{Runtime path equivalence and typing modulo equivalence}

Runtime path equivalence \(p\runtimeeq q\) is the least path congruence
relating paths that resolve to the same location in \(\sigma\). Conversion
along this equivalence relates a selected member opened at \(p.1\) to the same
member opened at the location returned by that projection.

The auxiliary judgments for paths, subtyping, terms, continuations, and states
extend the corresponding source rules with conversion along a path
congruence. For a congruence \(R\), write \(\Gamma\struct_R J\) for such a
judgment; \(\Gamma\struct_{\sigma}J\) abbreviates the instance
\(R=\runtimeeq\). A representative rule replaces equivalent paths inside a
type:
\[
\inferrule
  {p\runtimeeq q}
  {\Gamma\struct_{\sigma}
    \subst{\tau}{p}{x}<:\subst{\tau}{q}{x}}.
\tag{Conversion}
\]
Because \(\runtimeeq\) is a congruence, the same principle applies beneath
projections, selections, functions, and pair signatures.

\subsection{Realization and semantic coercions}
\label{sec:realization}

Endpoint resolution in \cref{fig:runtime-proof} follows both term and type
members. A value endpoint realizes a proper type, while a type-definition
endpoint realizes an interval. The rules in
\cref{fig:realization,fig:coercions} record the data used in the
canonical-forms proof. For
an exact closure with signature \((z:A)\to B\) observed at
\((z:S)\to U\), function realization records \(S<:A\) and, under \(z:S\),
\(B<:U\). The former checks an actual argument against the closure domain;
the latter subsumes the opened body at the advertised result type. Pair
realization records realizations of the first component and of the member
opened at that component. Singleton realization is resolution to the
designated location; selection realization first resolves the type member to
its stored definition.

Interval realization is the recursive point of the interpretation. If a
stored definition \(W\) realizes \(L..U\), the proof needs operations taking
realizers of \(L\) to realizers of \(W\), and realizers of \(W\) to realizers
of \(U\). Placing those operations directly in the definition as functions
would put the realization relation to the left of an arrow in its own mutual
definition. We therefore defunctionalize them as an inductive family of finite
derivations, written
\(\Gamma;\sigma\vdash\tau_1\semmap\tau_2\), called semantic coercions. This
auxiliary relation is used to establish canonical forms for the CK machine of
\cref{fig:dynamics}.

Each coercion constructor retains the auxiliary premises of the subtyping
rule it interprets. Reflexivity and transitivity become identity and
composition. Selection resolves the member definition and uses the lower or
upper coercion stored by interval realization. A function coercion retains
the domain and codomain comparisons used when the abstraction is applied.
First-component pair widening acts recursively on the stored component.
Interval subtyping composes its lower and upper maps in the variance-directed
order.

The dependent-member case accounts for the specialized source rule. A pair
whose first component \(y\) realizes \(\sing{p}\) satisfies
\(y\runtimeeq p\). Conversion first changes the realized member from
\(\subst{\tau}{y}{x}\) to \(\subst{\tau}{p}{x}\); the explicit opened
coercion from \textsc{S-Pair-Single} acts at \(p\); a second conversion changes
the result to \(\subst{\tau'}{y}{x}\). The pair coercion stores the opened map
and the auxiliary premises; its action performs the two conversions around
that map.

\begin{lemma}[Coercion construction, action, and erasure]
\label{lem:coercions}
The following properties hold.
\begin{enumerate}
\item If \(\storeexact(\Gamma;\sigma)\) and
  \(\Gamma\struct_{\sigma}\tau_1<:\tau_2\), then
  \(\Gamma;\sigma\vdash\tau_1\semmap\tau_2\).
\item If \(\Gamma;\sigma\vdash\tau_1\semmap\tau_2\) and
  \(e\in\llbracket\tau_1\rrbracket_{\Gamma,\sigma}\), then
  \(e\in\llbracket\tau_2\rrbracket_{\Gamma,\sigma}\).
\item If \(\Gamma;\sigma\vdash\tau_1\semmap\tau_2\), then
  \(\Gamma\struct_{\sigma}\tau_1<:\tau_2\).
\end{enumerate}
\end{lemma}

The first clause constructs a coercion from auxiliary subtyping in an exact
store; it is the identity instance of the fundamental lemma below. The second
clause is coercion action, and the third erases the semantic evidence.

\subsection{Fundamental lemma and canonical forms}

The central induction is a simultaneous substitution argument using the
realized-substitution judgment in \cref{fig:realization}. It requires
auxiliary checking of substituted context bindings, preservation of the path
relation, and endpoint realization. These hypotheses provide the endpoint
needed when the induction crosses a binder.

\begin{lemma}[Fundamental lemma]
\label{lem:fundamental}
Suppose \(\rho\models^R_{\Delta,\sigma}\Gamma\).
\begin{enumerate}
\item If \(\Gamma\struct_R p::\tau\), then for some \(e\),
  \(\sigma\vdash\rho(p)\resolve e\) and
  \(e\in\llbracket\rho(\tau)\rrbracket_{\Delta,\sigma}\).
\item If \(\Gamma\struct_R\tau_1<:\tau_2\), then
  \(\Delta;\sigma\vdash
    \rho(\tau_1)\semmap\rho(\tau_2)\).
\end{enumerate}
\end{lemma}

A realized substitution carries the store facts required by the induction.
For an exact store, the identity substitution satisfies
\(\mathsf{id}\models^{\runtimeeq}_{\Gamma,\sigma}\Gamma\), which is the
instance used by the runtime proof.

The cases for selection use interval realization; transitivity composes
coercions. In the singleton-pair case, the induction stores the coercion
obtained from the explicit comparison opened at \(p\). When that coercion is
applied to a realized pair, runtime path equivalence transports it to the
actual first component. Instantiating \cref{lem:fundamental} with the identity
substitution gives \cref{lem:path-resolution} and constructs a semantic
coercion for every auxiliary subtyping derivation in an exact store.

Applying such a coercion to the realization of a location singleton yields
the canonical forms used by the machine.

\begin{lemma}[Canonical forms]
\label{lem:canonical}
Let \(\sigma\) be exact for \(\Gamma\).
\begin{enumerate}
\item If \(\Gamma\struct_{\sigma}\sing{x}<:(z:S)\to T\), then
  \(\sigma(x)\) is an
  abstraction.
\item If \(\Gamma\struct_{\sigma}\sing{x}<:\pairty{z}{S}{a}{\tau}\), then
  \(\sigma(x)\) is a pair.
\end{enumerate}
\end{lemma}

The function case also recovers the exact closure signature and the residual
subtypings relating it to \((z:S)\to T\). Preservation for dependent beta
reduction uses the recovered signature and these residual derivations.

\subsection{Progress and preservation}

\begin{theorem}[Progress]
\label{thm:progress}
If \(\Gamma\struct_{\exact}s:T\), then \(s\) is final or there exists \(s'\)
such that \(s\sstep s'\).
\end{theorem}

\begin{theorem}[Preservation]
\label{thm:preservation}
If \(\Gamma\struct_{\exact}s:T\) and \(s\sstep s'\), then for some
\(\Delta,U\),
\[
(\Gamma,T)\preceq(\Delta,U)
\qquad\text{and}\qquad
\Delta\struct_{\exact}s':U.
\]
\end{theorem}

Progress proceeds by cases on the current term of an exactly typed runtime
state. Path terms use \cref{lem:path-resolution}. An application resolves the
operator and operand paths, and \cref{lem:canonical} exposes an abstraction
at the operator location. Pair canonical forms supply the inversion needed by
first projection and labelled selection during path resolution.

Preservation is by cases on the machine step. If
\(\sigma\vdash p\resolve\mathsf{val}(x)\), runtime path equivalence converts
\(\sing{p}\) to \(\sing{x}\) inside the invariant, preserving the enclosing
auxiliary term judgment. Beta reduction uses the closure signature and
residual comparisons obtained from function realization after coercion
action.
When a let-bound value is allocated, exact value inversion determines the new
store binding, narrowing checks the suspended body at that exact type, and
the old continuation remains syntactically unchanged while its typing is
weakened into the extended store context. The remaining administrative steps
preserve the invariant. Iterating
\cref{thm:preservation} proves \cref{thm:reachable}; applying
\cref{thm:progress} at the endpoint proves \cref{thm:safety}.

\section{Related work}

DOT combines abstract type members with recursive objects, refinements,
intersections, and a rich subtyping lattice
\citep{amin2014foundations,rompf2016dot}. Its soundness proofs must control
which abstract bounds can be exposed in arbitrary contexts. The tight-typing
account of \citet{rapoport2017simple}, for example, factors reasoning through
inert contexts in which runtime values admit strong inversion principles.

For \lambdap{}, the exact-store invariant provides the required inversion
principle: a location retains the introduction type of its stored
function or pair even when declarative subtyping presents it at another type.
Semantic coercions interpret primitive transitivity and abstract selection
without a separate inert/tight-typing judgment.

pDOT adds arbitrary-length paths and singleton types to recursive objects and
gives a Coq-mechanized safety proof \citep{rapoport2019pdot}. \lambdap{}
represents record extension by dependent-pair chains, with explicit hit and
miss rules for static selection and dynamic lookup. Removing recursive
objects, intersections, and unions leaves path lookup as a distinct obligation
in the safety proof.

\section{Conclusion}

\lambdap{} isolates paths, dependent pairs, and abstract type members. Its
counterexample shows that abstract membership cannot justify singleton
symmetry. The safety proof combines exact stores, runtime path equivalence, and
semantic coercions for the restricted pair rule. Whether unrestricted pair
subtyping is sound for \lambdap{} remains open.
