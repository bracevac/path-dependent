\title{\texorpdfstring{\lambdap}{lambda-p}: Paths through Dependent Pairs}
\author{Anonymous Author(s)}
\renewcommand{\shortauthors}{Anonymous Author(s)}

\begin{document}

\begin{abstract}
We present \lambdap{}, a calculus in which paths traverse immutable dependent
pairs. A pair member may depend on the first component and may contain either
a term reference or a type definition. The calculus distinguishes term
singleton types from abstract type selections. Conflating the two makes
singleton symmetry unsound: we give a closed, well-typed program that becomes
stuck. We adopt a conservative rule for dependent-pair subtyping and prove
finite-run type safety in Lean. The unrestricted pair rule remains an open
question for the syntax-separated calculus.
\end{abstract}

\keywords{path-dependent types, dependent pairs, singleton types, type
soundness, Lean}

\maketitle

\section{Introduction}

A path-dependent type assigns a type component to a stable term path. The
usual object-calculus presentation combines this mechanism with recursive
objects, refinements, intersections, and a substantial subtyping relation
\citep{amin2014foundations,rompf2016dot}. The purpose of \lambdap{} is
narrower: to isolate paths, abstract type members, and dependency between the
two components of a pair.

Values in \lambdap{} are functions and immutable dependent pairs. A pair
contains a first component and either a term reference or a type definition;
the member signature may mention the first component. Paths follow first
projections and named members through chains of pairs. A missed label resumes
the search in the first component, making record lookup a direct traversal of
the pair chain.

For example, let \(r_1=\pairval{b}{a}{z}\) and
\(r_2=\pairval{r_1}{A}{T}\). Selection \(r_2.A\) hits the outer type member,
whereas \(r_2.a\) misses \(A\) and continues as \(r_2.1.a\), eventually
returning \(z\). The signature of the outer member may refer to its binder for
\(r_1\), so the same pair structure supports both record extension and
dependency on the preceding component.

Two design choices carry the metatheoretic weight. First, the singleton type
\(\sing{p}\), which expresses value identity, is distinct from the abstract
selection \(p.A\), which denotes a type between declared bounds. An earlier
version represented both with one constructor. We show that singleton
symmetry then turns abstract membership into a false path equality and yields
a closed stuck program.

Second, dependent-pair subtyping is conservative. The first-component type
may be widened separately; the dependent member may change only while the
first component is a singleton, with an explicit comparison after opening at
that path. This rule supports the intended abstraction examples and supplies
the evidence used by a direct semantic proof. It is not known whether the
unrestricted rule is unsound after singletons and selections are separated.

\paragraph{Contributions.}
The paper gives a closed counterexample showing that abstract membership
cannot justify singleton symmetry; a calculus that separates those notions
and retains dependent abstract members with explicit bound checks; and a
direct finite-run safety proof based on exact stores, co-resolution of paths,
and proof-relevant semantic coercions. The complete development is formalized
in Lean. The language deliberately omits recursive objects, mutation,
intersections, and unions; declarative transitivity remains primitive.

The binder \(x\) in a function scopes over its codomain. In
\(\pairty{x}{S}{a}{\tau}\), it scopes over the member signature \(\tau\).
We write \(\subst{\tau}{p}{x}\) for capture-avoiding opening. Terms are in
monadic normal form: pair components are variables, and both sides of an
application are paths.

The four source judgments are
\[
\Gamma\vdash p::\tau^\kappa
\qquad
\Gamma\vdash\tau_1^\kappa<:\tau_2^\kappa
\qquad
\Gamma\vdash\tau^\kappa\ \wf
\qquad
\Gamma\vdash t:T.
\]
The double colon denotes \emph{precise path typing}: unlike term typing, it
does not contain subsumption.

\subsection{Dynamics}

A store \(\sigma\) is an immutable sequence of values, and a stored value may
refer only to earlier cells. We write \(\sigma(x)=v\) for lookup and
\(\sigma,x\mapsto v\) for extension at a fresh location.

Source path resolution, written \(\sigma\vdash p\resolve x\), is big-step.
Projection returns the stored first component, a matching term member returns
its stored location, and a missed label continues from the first component.
Resolution is deterministic but partial on arbitrary stores; totality for
well-typed paths is part of the soundness argument.

Machine states are triples \(\langle\sigma,K,t\rangle\), with continuations
made only of let frames. The rules at the bottom of \cref{fig:dynamics}
resolve applications and paths, evaluate let-bound computations, and
allocate syntactic values. Store extension weakens the old continuation,
written \(K^\uparrow\), into the extended scope. Application first resolves
both operand paths and then requires an abstraction at the operator location;
this is the case for which canonical forms are essential.

\section{Two design decisions}
\label{sec:pairs}

\subsection{Singletons and abstract selections}

The term singleton \(\sing{p}\) asserts value identity. In particular,
\textsc{S-Alias} is justified when precise typing says that one path has
another path's singleton type. An abstract selection \(p.A\), by contrast,
denotes an unknown type between the bounds stored at \(A\). Membership in
\(p.A\) says nothing by itself about path identity.

In a precursor to \lambdap{}, both forms used one type constructor, so
singleton symmetry accepted either role. Let
\[
\begin{array}{rcl}
f &=& \lambda(x:\top).x,\\
q &=& \pairval{f}{A}{\top},\\
h &=& \lambda(z:q.A).q.
\end{array}
\]
The historical rules type the body of \(h\) by the chain
\[
  \sing{q}<:\top<:q.A<:\sing{z}.
\]
The last edge applies singleton symmetry to the context binding \(z:q.A\),
treating abstract membership as equality. The same rules accept \(f\) as an
argument of type \(q.A\). Thus \(h\,f\) is assigned \(\sing{f}\), although it
returns \(q\).

Consequently, the closed program
\[
\begin{array}{l}
\mathbf{let}\ f=\lambda(x:\top).x\ \mathbf{in}\\
\mathbf{let}\ q=\pairval{f}{A}{\top}\ \mathbf{in}\\
\mathbf{let}\ h=\lambda(z:q.A).q\ \mathbf{in}\\
\mathbf{let}\ r=h\,f\ \mathbf{in}\ r\,f
\end{array}
\]
reaches an application whose operator location contains the pair \(q\). It is
neither final nor reducible. Every interval in the derivation is
\(\top..\top\), so this is not a bad-bounds example. The failure also does
not hinge on primitive transitivity: an admissible transitivity lemma would
compose the same chain.

In the present syntax, a binding \(z:q.A\) cannot be a premise for
\textsc{S-Alias}; the historical derivation and execution are machine checked
separately.

The counterexample shows that singleton symmetry must distinguish term
identity from abstract membership. Separate constructors make this
distinction explicit, although a suitably guarded symmetry rule would be
another possible repair.

\subsection{The pair rule}

The unrestricted rule one might first write is
\[
\inferrule
  {\Gamma\vdash S<:S'
   \\
   \Gamma,x:S\vdash\tau<:\tau'}
  {\Gamma\vdash
    \pairty{x}{S}{a}{\tau}
    <:
    \pairty{x}{S'}{a}{\tau'}}.
\tag{Unrestricted Pair}
\]
Its semantic interpretation must work for the actual run-time first
component \(y\). In particular, a coercion between the pair types must later
turn a realization of \(\subst{\tau}{y}{x}\) into one of
\(\subst{\tau'}{y}{x}\). The induction hypothesis can construct such a
coercion once \(y\) and its realization are known, but a finite coercion for
the pair rule must be built before that run-time component is available.
Storing an inhabitant-indexed function in the coercion would make the
realization relation occur negatively in its own mutual definition.

\textsc{S-Pair-Single} fixes a path \(p\) and supplies that specialized
comparison explicitly. If the stored first component \(y\) has type
\(\sing{p}\), then \(y\) and \(p\) co-resolve. Run-time conversion transports
the opened comparison at \(p\) to the member opened at \(y\).

The two pair rules still support the intended abstraction pattern. If
\(\Gamma\vdash p::P\), then
\[
\begin{aligned}
&\pairty{x}{\sing{p}}{A}{\sing{p}..\sing{p}}
\\[-1mm]
&\quad<:\pairty{x}{\sing{p}}{A}{\bot..\sing{x}}
\\[-1mm]
&\quad<:\pairty{x}{P}{A}{\bot..\sing{x}}.
\end{aligned}
\]
The first step hides an exact definition behind dependent bounds while the
first component is a singleton; the second widens that component.

This is a proof-motivated conservative restriction, not a demonstrated
boundary of soundness. We have no counterexample to the unrestricted rule
after singleton types and abstract selections have been separated.

\section{Soundness}
\label{sec:soundness}

Write \(\initial(t)\steps s\) when the initial machine state of \(t\) reaches
\(s\) in finitely many steps. The source-facing result is the usual
non-stuckness theorem.

\begin{theorem}[Finite-run type safety]
\label{thm:safety}
If \(\ctxempty\vdash t:T\) and \(\initial(t)\steps s\), then
\(s\) is final or there exists \(s'\) such that \(s\sstep s'\).
\end{theorem}

The theorem ranges over finite executions and does not assert termination.
Preservation is proved for a stronger run-time invariant rather than by
extending the source term judgment to machine states.

Write \(\Delta\struct_{\exact}s:U\) when the store of \(s\) is recorded at
exact introduction types and its current term and continuation satisfy the
structural run-time judgments. Write
\((\Gamma,T)\preceq(\Delta,U)\) when \(\Delta\) extends \(\Gamma\) by
allocations and \(U\) is the corresponding weakening of \(T\).

\begin{theorem}[Finite-run preservation]
\label{thm:preservation}
If \(\ctxempty\vdash t:T\) and \(\initial(t)\steps s\), then for some
\(\Delta,U\),
\[
(\ctxempty,T)\preceq(\Delta,U)
\qquad\text{and}\qquad
\Delta\struct_{\exact}s:U.
\]
\end{theorem}

The changing context is bookkeeping forced by allocation: a fresh location
extends the store context, and the result type is weakened along that
extension. The exact structural judgment is the mathematical preservation
invariant; \cref{thm:safety} is its source-facing corollary.

\subsection{Path resolution and exact stores}

The first obstacle is path lookup. The tempting statement that resolution
preserves the precise synthesized type is false. Suppose a stored pair has
first component \(y\). The path \(p.1\) may synthesize \(\sing{y}\), whereas
the endpoint \(y\) synthesizes whatever type the store context assigns to
that location. These types are related, but not literally equal.

The proof instead separates totality from preservation. For the term fragment
of precise path typing, an exact well-typed store gives
\[
\begin{array}{c}
\Gamma\vdash p::T
\qquad
\mathsf{ExactStore}(\Gamma,\sigma)
\\ \hline
\exists x.\ \sigma\vdash p\resolve x.
\end{array}
\]
If \(p\) has ordinary term type \(T\) and resolves to \(x\), then \(x\) has
ordinary type \(T\). The induction follows the same hit and miss structure as
\textsc{P-Sel} and \textsc{P-Miss}; ordinary subsumption absorbs the change
from the path's precise type to the context type of its endpoint.

Exactness is essential for the next step. An ordinary store typing may record
a location at any supertype of its stored value, hiding the information needed
by both lookup and canonical forms. The lookup lemmas above are therefore
stated directly for exact stores. From a location viewed as a function one
must recover an abstraction and its original signature. An exact store records
the syntax-directed type assigned by
\textsc{T-Abs}, \textsc{T-Pair}, or \textsc{T-Type-Pair}. Allocation extends
the store with precisely this type; value inversion and narrowing recheck the
suspended let body under the more informative binding.

\subsection{Co-resolution and structural typing}

Reduction also changes the spelling of paths. Let \(p\runtimeeq q\) be the
least congruence containing paths that resolve to the same location in
\(\sigma\). Types admit conversion along this equivalence. For example, a
selected member opened at \(p.1\) must be related to the same member opened at
the location returned by the projection. Co-resolution supplies exactly that
equality.

The source judgments embed into proof-only structural judgments for paths,
subtyping, terms, continuations, and states. They expose the source
constructors and add conversion by \(\runtimeeq\). This layer is not an
extension of the source calculus: its purpose is to state the run-time
invariant and to make the conversion steps used by preservation explicit.
A representative rule is replacement of co-resolving paths inside a type:
\[
\inferrule
  {p\runtimeeq q}
  {\Gamma\struct
    \subst{\tau}{p}{x}<:\subst{\tau}{q}{x}}.
\tag{Conversion}
\]
Because \(\runtimeeq\) is a congruence, the same principle applies beneath
projections, selections, functions, and pair signatures.

\subsection{Realization and semantic coercions}

Source evaluation returns locations, but the proof must also account for type
members. It therefore uses generalized endpoints
\[
e ::= \mathsf{val}(x) \mid \mathsf{type}(W).
\]
On term paths, generalized resolution agrees with the source relation. A
value endpoint realizes a proper type; a type endpoint realizes an interval.
The defining clauses needed below are as follows. A location realizes a
function or pair type only if the store contains the corresponding value
form. It realizes \(\sing{p}\) when it co-resolves with \(p\). A stored
definition \(W\) realizes \(L..U\) together with evidence taking realizers of
\(L\) to realizers of \(W\), and realizers of \(W\) to realizers of \(U\).

That evidence is represented by a finite, proof-relevant semantic coercion
\(\tau_1\semmap\tau_2\). A coercion acts on endpoints:
\[
\inferrule
  {\tau_1\semmap\tau_2
   \\
   e\in\llbracket\tau_1\rrbracket_{\Gamma,\sigma}}
  {e\in\llbracket\tau_2\rrbracket_{\Gamma,\sigma}}.
\tag{Coercion action}
\]
Identity and composition interpret reflexivity and transitivity. Selection
uses the two coercions stored with an interval realization. Function
coercions retain the residual domain and codomain comparisons later needed by
beta reduction. Crucially, coercions are finite syntax rather than semantic
functions, keeping the mutually defined realization relation strictly
positive. The explicit opened premise of \textsc{S-Pair-Single} supplies the
finite member coercion that the unrestricted pair rule lacks.

\subsection{Fundamental lemma and canonical forms}

The central induction is a simultaneous substitution argument. A semantic
path substitution \(\rho\) from \(\Gamma\) to \(\Delta\) must satisfy three
conditions: each binding is mapped to a structurally checked path at its
substituted type; \(\rho\) maps the source structural path relation into
\(\runtimeeq\); and each mapped variable resolves to an endpoint realizing
its substituted context type. Under such a substitution, path checking and
subtyping have the following common interpretation.

\begin{lemma}[Fundamental lemma]
\label{lem:fundamental}
Suppose \(\rho\) realizes \(\Gamma\) in an exact store \((\Delta,\sigma)\).
\begin{enumerate}
\item If \(\Gamma\struct p::\tau\), then \(\rho(p)\) resolves to an endpoint
  realizing \(\rho(\tau)\).
\item If \(\Gamma\struct\tau_1<:\tau_2\), then
  \(\rho(\tau_1)\semmap\rho(\tau_2)\).
\end{enumerate}
\end{lemma}

The cases for selection use interval realization; transitivity composes
coercions. In the singleton-pair case, the first component co-resolves with
the fixed path \(p\), so run-time conversion transports the explicit opened
coercion to the actual component. Instantiating \cref{lem:fundamental} with
the identity substitution gives generalized path resolution and a semantic
coercion for every structural subtyping derivation in an exact store.

Applying such a coercion to the realization of a location singleton yields
the canonical forms used by the machine.

\begin{lemma}[Canonical forms]
\label{lem:canonical}
Let \(\sigma\) be exact for \(\Gamma\).
\begin{enumerate}
\item If \(\Gamma\struct\sing{x}<:(z:S)\to T\), then \(\sigma(x)\) is an
  abstraction.
\item If \(\Gamma\struct\sing{x}<:\pairty{z}{S}{a}{\tau}\), then
  \(\sigma(x)\) is a pair.
\end{enumerate}
\end{lemma}

The function case also recovers the exact closure signature and the residual
subtypings relating it to \((z:S)\to T\). Those residuals are what make
dependent beta reduction type preserving.

\subsection{Progress and preservation}

Progress is by induction on structural typing of the current term and
continuation. In an application, path resolution supplies locations for the
operator and operand, and \cref{lem:canonical} exposes an abstraction at the
operator. Projection and selection use the pair part of canonical forms and
the hit/miss correspondence between static and dynamic lookup.

Preservation is by cases on the machine step. If \(p\) normalizes to \(x\),
co-resolution permits structural conversion from \(\sing{p}\) to
\(\sing{x}\) inside the run-time invariant; the ordinary endpoint theorem
above explains why literal preservation of precise typing was the wrong
statement. Beta reduction uses the closure signature recovered by the
function coercion.
When a let-bound value is allocated, exact value inversion determines the new
store binding, narrowing checks the suspended body at that exact type, and
the old continuation is weakened into the extended scope. The remaining
administrative steps preserve the invariant directly. Iterating preservation
and applying progress at the endpoint proves \cref{thm:safety}.

The calculus, counterexample, and safety proof are mechanized in Lean 4
\citep{demoura2021lean4}.

\section{Related work}

DOT combines abstract type members with recursive objects, refinements,
intersections, and a rich subtyping lattice
\citep{amin2014foundations,rompf2016dot}. Its soundness proofs must control
which abstract bounds can be exposed in arbitrary contexts. The tight-typing
account of \citet{rapoport2017simple}, for example, factors reasoning through
inert contexts in which run-time values admit strong inversion principles.

\lambdap{} has no recursive self types or intersections and does not use an
inert/tight-typing split. The exact store invariant provides the narrower
inversion fact needed here: a location retains the introduction type of its
stored function or pair even when declarative subtyping presents it at another
type. Semantic coercions interpret the remaining subtyping derivation,
including primitive transitivity and abstract selection, rather than trying
to normalize it to a syntax-directed derivation.

pDOT adds arbitrary-length paths and singleton types to DOT and gives a
Coq-mechanized safety proof \citep{rapoport2019pdot}. It is the closest point
of comparison for path equality and abstract selection. In \lambdap{}, record
extension is instead represented by dependent pair chains, and both static
selection and dynamic lookup have an explicit missed-label case. The present
calculus asks which obligations remain when this path mechanism is separated
from recursive objects, intersections, and unions.

\section{Conclusion}

\lambdap{} isolates paths, dependent pairs, and abstract type members. Its
counterexample shows that abstract membership cannot justify singleton
symmetry. Separating the two notions and conservatively restricting pair
subtyping yields a direct finite-run safety proof. Whether unrestricted pair
subtyping is sound for the syntax-separated calculus remains open.
